# 손글씨 인식기 웹/데스크톱 분리 설계

## 목적

지금 저장소 루트에 평평하게 놓인 PyTorch + Tkinter 프로그램을 두 갈래로 나눈다.

- `desktop_version/` — 기존 코드를 그대로 옮긴다. 동작 변경 없음.
- `web_version/` — 외부 라이브러리 없이 순수 자바스크립트로 추론하는 새 정적 사이트.
  GitHub Pages에 올라간다.

웹 버전은 학습을 하지 않는다. `train.py`가 만든 `mnist_cnn.pt`를 변환해 쓰는
**추론 전용** 클라이언트다. 서버도 빌드 도구도 없다.

## 범위 밖

- 모델 구조 변경, 재학습, 정확도 개선
- 웹에서의 학습·파인튜닝
- 프레임워크(React 등), 번들러, 패키지 매니저
- TensorFlow.js·ONNX Runtime 등 추론 라이브러리 (요구사항이 "외부 라이브러리 없이")

## 1단계: 데스크톱 이동

`git mv`로 히스토리를 보존하며 옮긴다.

| 대상 | 이동 |
| --- | --- |
| `model.py` `train.py` `app.py` `점검.py` `아이콘_만들기.py` | → `desktop_version/` |
| `바로가기_만들기.ps1` `손글씨인식.ico` `mnist_cnn.pt` | → `desktop_version/` |
| `data/` (gitignore, 64MB) | → `desktop_version/data/` (일반 파일 이동) |
| `venv/` | **옮기지 않는다** |

### venv를 옮기지 않는 이유

`venv/pyvenv.cfg`와 `Scripts/`의 `pip.exe`·`activate`·`activate.bat` 등에
`C:\미니프로젝트\study01_MNIST\venv` 절대 경로가 박혀 있다. 폴더를 옮기면
pip과 activate가 깨진다. venv는 코드가 아니라 환경이고 gitignore 대상이므로
루트에 그대로 둔다.

`바로가기_만들기.ps1`은 `.\venv`와 `..\venv`를 모두 찾도록 고친다. 이것이
이동 과정에서 기존 파이썬 코드에 가하는 **유일한 수정**이다.

### 이동의 부수 영향

- 파이썬 코드의 `기준경로 = Path(__file__).resolve().parent`는 자동으로
  `desktop_version/`을 가리키므로 `mnist_cnn.pt`·`손글씨인식.ico`·`data/` 참조는
  그대로 맞는다. 수정 불필요.
- **바탕 화면 바로가기는 옛 경로를 가리켜 깨진다.** 이동 후
  `바로가기_만들기.ps1`을 다시 실행해야 한다. README와 CLAUDE.md에 명시한다.
- `.gitignore`는 **고칠 필요가 없다.** `data/`와 `손글씨인식_미리보기.png`는
  슬래시가 앞에 없는 패턴이라 어느 깊이에서도 일치한다. 이동 후에도 그대로 듣는다.
- 루트에 있는 `손글씨인식_미리보기.png`는 `아이콘_만들기.py`로 재생성되므로
  함께 옮기거나 지워도 무방하다.

## 2단계: 가중치 내보내기

`web_version/도구/내보내기.py`가 `desktop_version/mnist_cnn.pt`를 읽어 두 가지를 만든다.
torch가 필요하므로 데스크톱 환경(venv)에서 실행한다.

### 가중치.bin (float16, 약 2.4MB)

`state_dict`의 8개 텐서(`conv1.weight/bias`, `conv2.weight/bias`,
`fc1.weight/bias`, `fc2.weight/bias`)를 선언 순서대로 이어 붙인 리틀엔디언
float16 바이너리. 총 1,199,882개 값.

float16 선택 근거: 파라미터의 98%가 `fc1`(9216×128)에 몰려 있어 float32는 4.8MB다.
float16은 절반이고 MNIST 평가 정확도 손실이 사실상 0이다. int8은 층별 스케일 보정이
필요하고 정확도 위험이 실재해 택하지 않는다.

### 가중치_구조.json

각 텐서의 이름·모양·바이트 오프셋·길이. JS가 이 파일만 보고 `가중치.bin`을 자른다.
모델 구조를 바꾸면 이 파일이 함께 바뀌므로, 구조 변경 여부를 드러내는 역할도 한다.

## 3단계: 순수 JS 추론 엔진

### 모델.js

`숫자인식CNN.forward`를 그대로 옮긴다.

```
입력 1×28×28
합성곱(1→32, 3×3) → 렐루          # 28×28 → 26×26
합성곱(32→64, 3×3) → 렐루         # 26×26 → 24×24
최대풀링(2)                        # 24×24 → 12×12
펼치기(9216)
완전연결(9216→128) → 렐루
완전연결(128→10) → 소프트맥스
```

드롭아웃 두 개는 `model.eval()`에서 항등함수이므로 JS에 넣지 않는다.
파이썬은 `log_softmax` 후 `.exp()`로 확률을 얻지만 JS는 수치적으로 안정한
소프트맥스(최댓값 빼기)를 직접 계산한다. 결과는 같다.

연산량은 약 1,200만 MAC이다. 소박한 중첩 루프로 수십 ms에 끝나므로 WebGL·WASM·
라이브러리는 쓰지 않는다. `Float32Array`만 쓴다.

float16 → float32 디코딩은 `DataView.getFloat16`(ES2025)에 기대지 않고
비트 연산으로 직접 구현한다. 구형 브라우저 호환을 위해서다.

### 전처리.js

`app.py`의 `그림_전처리` 4단계를 순서까지 그대로 옮긴다.

1. 획이 있는 최소 사각형 찾기 (`getbbox` 동등)
2. 가로세로 비율 유지하며 긴 변을 20px로 LANCZOS 축소
3. 28×28 검은 바탕 가운데에 붙이기
4. 밝기 무게중심을 (13.5, 13.5)로 정수 평행이동

canvas `drawImage`의 축소는 **쓰지 않는다**. 브라우저마다 보간 결과가 달라
검증이 불가능해지기 때문이다. PIL의 Lanczos를 고정소수점 경로까지 JS로 구현한다.

1·3·4단계는 정수 연산이라 파이썬과 정확히 일치한다. 위험이 몰린 곳은 2단계뿐이다.

## 4단계: 검증

### 검증 계약의 경계 (중요)

PIL `ImageDraw`는 안티앨리어싱을 하지 않고 브라우저 canvas는 한다. 따라서
*같은 마우스 궤적*이 양쪽에서 같은 280×280 비트맵이 되지는 **않는다**. 이는
원리상 맞출 수 없고, 맞출 필요도 없다.

검증 가능하고 실제로 중요한 계약은 이것이다:

> **같은 280×280 비트맵을 넣으면 같은 28×28과 같은 확률이 나온다.**

전처리·추론 이식의 정확성은 이 계약으로 완전히 덮인다.

### 기준값.json

`점검.py`의 `손글씨_그리기(0~9)`가 만드는 280×280 그림을 골든 벡터로 쓴다.
`도구/내보내기.py`가 함께 생성한다. 숫자마다 세 가지를 담는다.

| 항목 | 형식 | 크기 |
| --- | --- | --- |
| 입력 280×280 | 1비트 packing → base64 | 약 13KB |
| 기대 28×28 | uint8 → base64 | 약 1KB |
| 기대 확률 10개 | float 배열 | 작음 |

획이 `fill=255`로만 그려져 화소가 0 또는 255뿐이므로 1비트 packing이 무손실이다.
전체 약 145KB 한 파일이면 된다.

### 점검.mjs

Node로 의존성 없이 실행한다(`node 점검.mjs`). 두 단계를 **독립적으로** 확인해
어느 쪽이 깨졌는지 바로 드러나게 한다. `점검.py`가 평가 정확도와 그린 획을
따로 확인하는 것과 같은 구조다.

1. **추론 엔진**: 기준 28×28 → 확률이 파이썬과 일치하는가
2. **전처리**: 기준 280×280 → 28×28이 파이썬과 일치하는가

### 합격선

목표는 28×28 화소 최대 오차 0, 확률의 **절대** 오차 1e-5 이내다.

PIL Lanczos의 고정소수점 재현이 1 LSB 어긋날 가능성이 남아 있어, 그 경우의
후퇴선은 **화소 최대 오차 ≤ 1, 예측 숫자 10/10 일치**다. 구현 후 실제 측정값을
`web_version/CLAUDE.md`에 기준선으로 기록한다.

float16 양자화로 확률이 파이썬 float32와 미세하게 달라지는 것은 정상이며,
1단계의 허용 오차는 이를 포함해 잡는다.

## 5단계: 웹 UI

데스크톱 화면 구성을 따른다. 왼쪽 280×280 검은 캔버스, 오른쪽에 큰 결과 숫자,
신뢰도 문구, 0~9 확률 막대 10개, 지우기/다시 인식 버튼.

데스크톱과 다르게 가져가는 점:

- **Pointer Events**로 그린다. 마우스·터치·펜이 한 코드로 처리되어 휴대폰에서도 쓸 수 있다.
- 화면에 보이는 canvas와 별개로 **안티앨리어싱 없는 280×280 `Uint8Array` 사본**에
  획을 직접 래스터화한다. `app.py`가 PIL 사본에 따로 그리는 구조와 같다.
  전처리 입력이 브라우저 렌더링에 흔들리지 않는다.
- 가중치 2.4MB를 받는 동안 불러오는 중 상태를 표시하고, 실패하면 한글로 안내한다.
- 획을 뗄 때 인식하는 동작은 데스크톱과 같다.

## 6단계: 배포

`.github/workflows/웹_배포.yml`이 main push 시 `web_version/`만 Pages 아티팩트로
올린다. `actions/upload-pages-artifact`와 `actions/deploy-pages` 공식 액션만 쓰고
빌드 단계는 없다(빌드할 것이 없다).

배포 주소는 `https://amanda759333.github.io/Study01_MNIST/`이고 사이트 루트가
곧 앱 루트다. 따라서 HTML의 경로 참조는 상대 경로로 쓴다.

**사용자 조치 필요**: 저장소 Settings → Pages에서 소스를 "GitHub Actions"로
한 번 바꿔야 한다. 이건 코드로 할 수 없다.

## 7단계: 문서

### 루트 CLAUDE.md (얇게)

공통 규약(모든 것을 한글로, 작성일시 주석)과 두 폴더의 역할, 그리고
**두 버전에 걸친 계약**을 적는다. 가장 중요한 경고:

> 모델 구조를 바꾸면 `mnist_cnn.pt` 재학습과 웹 가중치 재내보내기가 **둘 다** 필요하다.

기존 CLAUDE.md의 상세 내용은 desktop_version으로 내린다.

### desktop_version/CLAUDE.md

기존 CLAUDE.md의 명령·구조·불변조건·윈도우 함정을 그대로 옮기되:

- venv가 한 단계 위(`..\venv`)에 있다는 점 반영
- 이동 후 바탕 화면 바로가기 재생성이 필요하다는 점 추가
- 정규화 상수·전처리 계약이 이제 **웹 버전까지** 걸쳐 있다는 점 추가

### web_version/CLAUDE.md

- 외부 라이브러리·빌드 도구 금지 규칙과 그 이유
- `.pt` → `가중치.bin` 내보내기 절차 (데스크톱 venv 필요)
- `node 점검.mjs` 실행법과 측정된 기준선
- Pages 배포 방식과 설정 요구사항
- `전처리.js`가 `app.py`의 `그림_전처리`와 쌍을 이루므로 한쪽만 고치면 안 된다는 경고

### README.md

두 버전을 소개하고 각 폴더로 안내한다. 기존 상세 내용은 desktop_version 쪽으로
정리하고 루트는 짧게 유지한다.

## 구현 순서

1. 데스크톱 이동 + `바로가기_만들기.ps1` 수정 → `점검.py`로 무손상 확인
2. `도구/내보내기.py` → `가중치.bin`·`가중치_구조.json`·`기준값.json` 생성
3. `모델.js` → `점검.mjs` 1단계(추론 엔진) 통과
4. `전처리.js` → `점검.mjs` 2단계(전처리) 통과
5. `index.html`·`스타일.css`·`앱.js` → 브라우저에서 직접 써 보며 확인
6. 배포 워크플로
7. CLAUDE.md 3종 + README

각 단계는 다음 단계의 전제가 된다. 특히 3·4단계의 검증이 통과하기 전에는
UI를 만들지 않는다 — 엔진이 틀린 채로 UI를 붙이면 어디가 문제인지 가려진다.
